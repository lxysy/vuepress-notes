### 踩到的坑
- **跨盘符 `path.relative` 返回绝对路径**（Windows 特性），`rel.startsWith('..')` 判断失效 → 需同时判断 `path.isAbsolute(rel)`

- `decodeURI` 遇到含裸 `%` 或反斜杠的引用会抛 `URI malformed` → 包一层 safeDecode
- Typora 会读 stdout **最后 N 行**，日志必须全部走 stderr

## 补充：Typora 上传是即时的，新增 prune + keepLocalCopy

### 用户疑问
「Typora 里直接上传，图贴错了想改怎么办？是不是已经进图床了？」

### 答案（从代码路径确认）
是的。时序：Typora 存本地 → 调脚本 → `uploadAll` → `commitAssets`（**当场 push 到 GitHub**）→ 返回 URL → Typora 插入 → 移走本地文件。粘贴完成时图已在线上。

### 新增能力
- `scripts/images.js prune [--yes]`：扫 docs 下文本文件收集 `/owner/repo@ref/<path>` 引用，对比 `.assets-repo` 实际文件，列出无人引用者；`--yes` 才删（同时清 manifest 条目、自底向上删空目录、commit+push）。正则不绑定域名，换 CDN 仍有效。
- `scripts/images.config.json` 增加 `keepLocalCopy`（默认 false）。true 时 typora 模式保留本地源文件，便于改图/找回。只对 typora 生效——sync 必须删，否则下次提交又被扫到，会循环上传。
- 修了 typora 模式下 `--dry-run` 仍有副作用的 bug（会移文件、写 manifest）。

### 验证方式（可复用）
把 `.assets-repo` 的 origin 临时指向 `git init --bare` 的本地裸仓库，就能完整跑 commit+push 而完全不碰 GitHub；测完 `remote set-url` 还原 + `reset --hard <原HEAD>`。注意裸仓库默认 HEAD 是 master，推送目标是 main，`git log` 要显式写分支名，否则误判成「没推上去」。
- prune 基线：175 文件 / 175 引用 / 0 孤儿（引用解析无误的反向证明）
- 造孤儿两种（未跟踪 / 已提交）均正确识别与删除，空目录 `inbox/YYYY-MM-DD` 自底向上清掉
- keepLocalCopy=true 保留源文件，false 移入 `.images-trash/<日期>/`
