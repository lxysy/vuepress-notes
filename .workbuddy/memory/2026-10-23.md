## 图片体积 + 大纲定位偏移：方案调研（未实施，待用户确认）

### 项目事实（已验证）
- VuePress 1.9.7 + vuepress-theme-reco 1.6.17，Node 18 + `NODE_OPTIONS=--openssl-legacy-provider`
- CI：`.github/workflows/doc.yml`，push main → `npm ci` → build → `peaceiris/actions-gh-pages@v3` 强推 gh-pages
- 图片 187 张 / 22.78 MB，165 张集中在 `docs/src/ai/img`；`.git` 107 MB（size-pack 68.17 MB）；dist 38 MB

### 问题 1：图片体积
- 实测（全量 187 张）：无损 PNG 重压缩 → 10.05 MB（-55.9%）；全量 WebP q82 → 10.04 MB（-55.9%）；智能择优 + 限宽 1600px → 6.64 MB（-70.9%）
- 关键结论：**只有「压缩源文件」和「图床外链」能改善本地 git push；懒加载 / 构建期压缩改善的是访客速度与 gh-pages 产物，不影响 push**
- **Git LFS 不推荐**：GitHub Pages 链路需额外配置，且对单次 push 上传量无本质改善
- 历史瘦身需 `git filter-repo` 重写历史（force push），或用 `git gc --aggressive`（收益有限）

### 问题 2：大纲点击偏移（根因已定位到源码）
链路：`SubSidebar.vue` 的 `<router-link to="/path#slug">` → `vuepress-plugin-smooth-scroll/lib/enhanceApp.js` 覆盖的 `router.options.scrollBehavior` → `window.scrollTo({top: getElementPosition(el).y, behavior:'smooth'})`
四重叠加：
1. `<img>` 无 width/height → 图片不占位，点击时算出的标题 Y 是"未加载"状态的坐标（主因）
2. scrollTo 目标是动画开始时的快照值，动画期间图片陆续 onload → 文档下移
3. 未扣除 position:fixed 的 navbar（3.6rem ≈ 58px）
4. 本项目放大项：Mermaid 走 CDN 异步加载 + setTimeout 200ms 后渲染，文本 → 大块 SVG

### 拟实施方案（待确认）
- 新增 `docs/.vuepress/plugins/markdown-it-image-size.js`：包装默认 image 规则（不覆盖），注入 `width/height/loading=lazy/decoding=async`
- 已验证可行性：`@vuepress/markdown-loader/index.js` 会向 `markdown.render(content, {loader, frontmatter, relativePath})` 传 `relativePath`，插件可据此解析图片真实路径
- 已验证执行顺序：`@vuepress/core/lib/node/App.js` 中 internal plugins 最后注册 → 用户的 `docs/.vuepress/enhanceApp.js` 最后执行 → 能覆盖 smooth-scroll 的 scrollBehavior
- 在 `enhanceApp.js` 中重写 scrollBehavior：逐帧 rAF 重算目标位置 + 减去 navbar 实测高度 + 用户操作可中断
- CSS 补一条 `.theme-reco-content img { height: auto }`（主题目前只有 max-width:100%）
